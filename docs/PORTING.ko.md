# Misskey Spreadsheet Mode — 설치·포팅 안내

이 프로젝트는 내려받아 프런트엔드에 통합하는 **소스 모듈**입니다. AiScript 플러그인이나 CSS 테마가 아닙니다. 서버 관리자가 소스를 복사하고 호스트 연결부를 맞춘 뒤 프런트엔드를 다시 빌드해야 합니다. 설치 후 사용자는 메뉴의 **시트모드 / Spreadsheet mode** 버튼으로 `/sheet`에 진입합니다.

라이선스는 AGPL-3.0-only입니다. 포함된 COPYING과 SPDX 표기를 유지하세요. 별도의 외부 서비스, OAuth 클라이언트, 계정 통합, 백엔드 API나 DB 스키마 추가는 필요하지 않습니다.

## 디렉터리 구성

- `src/index.ts`: 공개 진입점과 `SheetModule`, `SheetHost` 타입.
- `src/host.ts`: 호스트 연결 계약과 Vue provider. 필요한 어댑터가 없으면 오류를 표시합니다.
- `src/*.vue`: 독립 레이아웃, 노트 행, 알림, 셀 편집기.
- `src/state.ts`, `src/submission.ts`: 조회 상태와 중복 게시 방지.
- `adapters/misskey.ts`: 참고 호스트 어댑터. 버전별 내부 의존성은 여기에 둡니다.
- `integration/files/`: 전체 화면 셸, 라우트 진입점, 번역 로더용 데이터.
- `integration/misskey.patch`: 참고 프런트엔드의 작성기, 노트 상태 구독, 설정, 메뉴, 라우팅 연결 패치. 적용 전 검토하고 버전에 맞게 수정하세요.
- `test/unit/`: 핵심 동작 테스트. 이 저장소에서 `npm test`로 실행하며, 테스트 어댑터는 호스트 전역 상태에 의존하지 않습니다.

본체에는 런타임 `@/`, `@@/` 경로 참조나 Noctemblith 브랜드 문자열이 없습니다. 실행 시 Vue, 모듈 내부 파일, 주입된 `SheetHost`를 사용합니다. `misskey-js` 타입은 컴파일 시 호스트가 제공하며, 번역 문자열은 모듈 자체 계약을 사용합니다. 호스트의 기존 CSS 테마 변수와 버튼 유틸리티가 필요합니다. Misskey 내부 컴포넌트는 본체가 직접 가져오지 않고 어댑터로 공급합니다.

## 참고 프런트엔드에 설치

배포 중인 컨테이너 내부가 아닌 **소스 체크아웃**에서 작업하고, 기존 변경 사항을 먼저 보존하세요. 참고 패치는 Noctemblith 커밋 `14d4d625d` 기준입니다. 임의의 Misskey 버전과의 호환성은 아직 검증하지 않았습니다.

1. 소스 압축 파일을 풀거나 저장소를 복제합니다. 모듈 루트에서 아래 명령을 실행합니다.

   ```sh
   node scripts/sync-host.mjs /absolute/path/to/host --check
   node scripts/sync-host.mjs /absolute/path/to/host --write
   ```

   `--check`는 차이를 확인하고, `--write`는 `src/`를 호스트의 `packages/frontend/src/ui/sheet/`로 복사합니다. 참고 어댑터도 해당 경로의 `adapters/`에 설치하며 상대 import 경로를 조정합니다.

2. `integration/misskey.patch`를 검토한 뒤 호스트 저장소 루트에서 적용 가능 여부를 확인합니다.

   ```sh
   git apply --check /path/to/sheet-mode/integration/misskey.patch
   ```

   문제가 없으면 `git apply`로 적용합니다. 실패하면 강제로 적용하지 말고 필요한 연결부를 수동으로 이식하세요.

3. `integration/files/`의 파일을 호스트 저장소의 동일한 상대 경로로 복사합니다. 메뉴는 `navbar.ts`, 로그인 필수 라우트는 `router.definition.ts`, 전체 화면 셸은 초기 부팅 코드에 연결됩니다. 라우트 페이지는 보조 라우터와 창에서도 공통 UI가 중복되지 않도록 구성되어 있습니다.

4. 번역을 호스트 i18n 로더에 연결합니다. Crowdin이 관리하는 한국어·영어 YAML을 직접 덮어쓰지 마세요. 포함된 `noctemblith-sheet.ts`의 `noctemblithSheetTranslations`를 가져와 현재 언어 또는 영어 대체값으로 `_sheetMode`를 병합합니다. 참고 로더 코드는 다음과 같습니다.

   ```ts
   const sheetCopy = noctemblithSheetTranslations[lang] ?? (lang === 'ja' ? undefined : noctemblithSheetTranslations.en);
   if (sheetCopy) a[key]._sheetMode = { ...sheetCopy };
   ```

   기존 로더 import 옆에 import를 추가하세요. 패치는 기준 일본어 키를 추가합니다. 호스트 명령으로 번역 타입을 재생성하고 i18n을 빌드하세요. 다른 포크의 로더를 Noctemblith 로더 전체로 교체하지 마세요.

5. 이 저장소의 `adapters/misskey.ts`를 호스트에 맞게 수정하고 동기화를 다시 실행합니다. 컴포넌트 경로, `useNote`, 권한 검사, API 래퍼, 설정·알림 경로, 번역 객체, 라우터, 계정별 환경설정 저장소를 확인하세요. 시트 문서 제목도 호스트 인스턴스 이름을 사용해 여기에서 설정합니다.

6. 프런트엔드 타입 검사, 변경 파일 린트, 핵심 테스트를 실행한 뒤 호스트의 기존 빌드 절차로 빌드합니다. 실제 브라우저 검증까지 마쳐야 설치가 완료됩니다. 배포는 운영자가 별도로 결정합니다.

동기화 명령은 본체와 참고 어댑터만 복사합니다. 연결 패치를 자동 적용하거나 인증·DB·배포 설정을 수정하지 않습니다.

## 최소 호스트 연결 예시

```vue
<template><SheetModule :host="host"/></template>
<script setup lang="ts">
import { SheetModule } from './sheet/index.js';
import { host } from './my-sheet-host.js';
</script>
```

이 페이지를 로그인이 필요한 `/sheet` 라우트에 등록하고, 표 아이콘과 함께 해당 경로로 이동하는 메뉴를 추가하세요. 전체 화면 구성에는 참고 셸을 사용할 수 있습니다. `withCommon`의 기본값은 `false`입니다. 일반적으로 바깥 호스트 레이아웃이 팝업 등 공통 UI를 관리하므로, 그 레이아웃 밖에 렌더링할 때만 켜세요. 링크·팝업 컴포넌트가 요구하면 호스트 레이아웃에서 라우터 컨텍스트도 제공해야 합니다.

참고 메뉴 연결은 메뉴 사용자 지정과 ‘더 보기’를 지원합니다. 저장된 메뉴에 새 항목이 없는 기존 계정도 접근할 수 있도록 홈 링크 옆에 대체 진입 항목을 제공합니다. `sheetMode`는 홈 화면을 시트로 여는 선택적 저장 설정입니다. 꺼져 있어도 `/sheet` 직접 진입은 가능합니다. 일반 모드 복귀 시 해당 설정을 해제하고 홈으로 이동합니다.

## 호스트 연결에서 지켜야 할 계약

- **작성기:** `reply`, `sheet`, `compact`, `freezeAfterPosted`를 받고 `posted`, `cancel`, `esc` 이벤트를 내보냅니다. `isPosting`, `canClose`, `seedSheetText`를 노출해야 합니다. 간략·전체 작성기 전환 시 같은 작성기 인스턴스를 유지하세요. `reply`는 `notes/create`의 실제 `replyId`가 되어야 하며, 원본 수정 대상으로 전달하면 안 됩니다. 참고 작성기 패치는 계정별 초안 키, IME 조합 중 게시 방지, 확인·업로드·API 대기 구간을 포함한 중복 전송 방지를 제공합니다. 같은 계약을 구현하는 다른 작성기로 대체할 수 있습니다.
- **노트 상태 연결:** 하드·소프트 뮤트, 플러그인 필터링, 권한에 맞는 기존 액션, 순수 리노트의 표시 대상을 유지하세요. 시트 경로에서는 `useNote`의 스트리밍·폴링 구독을 꺼야 합니다. 참고 패치는 `manualRefresh`를 추가하며, 다른 포크는 실시간 구독이 없는 어댑터를 구현해도 됩니다. 일반 타임라인의 실시간 설정을 전역으로 끄지 마세요.
- **조회:** 한 번에 30개와 원본 `untilId` 커서를 사용합니다. 타이머, 스트리밍, 자동 행 삽입·정렬은 사용하지 않습니다. 최종 권한 판단은 백엔드가 담당하며, 어댑터에서도 사용할 수 없는 탭을 비활성화하세요.
- **알림:** 노트와 구분되는 별도 객체입니다. 호스트의 서버 측 읽음 처리가 끝난 뒤 `fetchNotifications`를 완료하세요. 참고 어댑터는 `i/notifications`에 `markAsRead: true`를 전달하며, 참고 구현은 모든 알림을 읽음으로 처리합니다. 다른 포크의 규칙이 다르면 읽음 처리를 먼저 수행하거나 읽음 상태 렌더러를 맞추세요. 알림 행 ID와 관련 답글 대상 노트 ID는 분리해야 합니다.
- **표현:** 안전한 MFM·링크·계정·시각 컴포넌트, CW 제어, 민감 미디어 보호가 적용된 뷰어를 공급하세요. 원시 HTML로 대체하지 마세요. 설정·알림·노트·계정 경로와 제목은 호스트 설정입니다.
- **생명주기:** 루트 셸보다 먼저 환경설정을 초기화하고 시트 직접 진입에도 인증을 요구하세요. 공통 팝업 호스트는 하나만 유지합니다. 기존 일반 UI, 인증, 권한, 서버 정책을 보존하세요.

## 검증과 호환성

참고 테스트는 답글 ID 정합성(순수 리노트와 반복 알림 포함), 새 노트, 전체 작성기 전환 시 초안 유지, IME, Enter·방향키, 페이지 추가 조회, 오래된 응답, 조회·편집 경합, 접근 불가 탭, 중복 게시 방지를 확인합니다. 운영 어댑터 대신 테스트 호스트를 주입하므로 다른 호스트에서도 본체를 실행할 수 있는 구조를 검증합니다.

포팅 결과를 배포하기 전 실제 게시·실패·재시도, 공개 범위·CW·민감 미디어, 차단·뮤트, 로그인·계정 전환, 데스크톱·모바일 메뉴 진입과 복귀, 라우트 새로고침, 실제 IME, 공통 팝업을 확인하세요. 모든 Misskey 버전과 자동 호환된다는 뜻은 아닙니다. 호스트 내부 기능을 재사용하므로 포크마다 참고 연결부를 검토하고 조정해야 합니다.

Misskey 번역 인라이너와 연결할 때는 참고 어댑터처럼 개별 번역 문자열을 명시적으로 전달하세요. 원본 I18n 싱글턴을 호스트 경계 너머로 넘기면 운영 빌드의 번역 인라이닝이 실패합니다.

## 배포용 소스 압축 파일 만들기

```sh
node scripts/package.mjs /absolute/output/misskey-spreadsheet-mode-source.tar.gz
```

압축 파일은 허용 목록에 있는 `src/`, `adapters/`, `integration/`, 테스트, 스크립트, 문서를 담습니다. Git 저장소 메타데이터, 배포 설정, 자격증명, DB, 빌드 캐시, `node_modules`는 포함하지 않습니다. 원격 저장소나 패키지 레지스트리에 공개하는 작업은 별도입니다.
